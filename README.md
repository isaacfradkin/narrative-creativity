# Narrative Twist (NT)

Scores how much each sentence of a story is a **narrative twist**, using a
language model. Method agreed with Itzik Fradkin & Anna Gorbunov (spec:
*"Dan and Anna – Narrative Creativity"*).

## The idea

For a target sentence **S2** in a story, with **S1** = all preceding sentences
and **S3** = the continuation:

```
nt = log( P(S3 | S1, S2) / Q ),     Q = mean_i P(S3 | S1, S2*_i)
```

where the **S2\*** are banal alternative sentences generated by the model.
`nt > 0` means the real sentence makes its continuation more likely than a banal
one would — i.e. a twist. All probabilities are **per token** (length-normalised,
perplexity-style) so sentences of different lengths are comparable.

Settings (fixed with Itzik): S1 = full context; S3 computed in **two modes**,
`next` (next sentence) and `all` (all following sentences); alternatives sampled
at **temperature 1**, ~10 per sentence; **one score per sentence** — aggregation
to story level is done later in R by Anna.

## Files

| File | Role |
|------|------|
| `narrative_twist.py` | Scoring **engine**: the `narrative_twist()` score + two model backends (`HFBackend`, `LlamaCppBackend`). Run it directly for a quick twist-vs-banal self-test. |
| `run_texts.py` | **Batch pipeline**: reads a stories `.xlsx`, scores every sentence, writes three `.xlsx`. |
| `COLUMNS.pdf` / `.tex` | One-page explanation of the method and of every output column. |
| `data/` | Input story files (`Texts.xlsx` = full dataset; `ten stories with clear NTs.xlsx` = the annotated subset). |
| `models/` | The GGUF model file (`Hebrew-Mistral-7B.Q4_K_M.gguf`). |
| `requirements.txt` | Dependencies. |

## Setup

The archive does **not** include the virtual environment or the model file
(~4.2 GB) — recreate them locally:

```bash
# 1) Create the virtual environment and install dependencies
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2) Download the model and place it at:
#      models/Hebrew-Mistral-7B.Q4_K_M.gguf
#    (Q4_K_M GGUF of https://huggingface.co/yam-peleg/Hebrew-Mistral-7B —
#     see models/DOWNLOAD_MODEL.txt for details)
```

There is **no model-download script**: the GGUF file is fetched manually and put
in `models/`. To use a different location, pass `--model /path/to/model.gguf`.

## Run

```bash
# Full run on a stories file (Hebrew model):
python run_texts.py --input "data/ten stories with clear NTs.xlsx" \
                    --output ten_stories_NT.xlsx --backend llamacpp

# The full dataset (122 participants x 2 stories):
python run_texts.py --input data/Texts.xlsx --output all_NT.xlsx --backend llamacpp

# Fast plumbing test, no 7B (distilgpt2 — English model, scores not meaningful):
python run_texts.py --input "data/ten stories with clear NTs.xlsx" \
                    --output /tmp/test.xlsx --backend hf --limit 1
```

Useful flags: `--limit N` (first N participants), `--participants 14485,14649`
(specific IDs), `--n-alternatives`, `--temperature`, `--seed` (the run is
reproducible for a fixed seed).

### Input format
First sheet with a `participant` column plus story columns — either
`paraphrase_text_1` / `paraphrase_text_2` (full dataset) or a single `story`
column. The pipeline auto-detects which are present.

## Outputs (`--output X.xlsx`)

| File | One row per | Key columns |
|------|-------------|-------------|
| `X.xlsx` | sentence | `nt_next`, `nt_all` (the score under each S3 mode) |
| `X_debug.xlsx` | sentence × S3 mode | `nt`, `log_post`, `log_prior`, `ratio`, `num_alternatives` |
| `X_alternatives.xlsx` | sentence × mode × alternative | `role` (real_S2 / alternative), `sentence`, `log_prob` |

See `COLUMNS.pdf` for the full description and formulas.

## Notes for whoever picks this up

- **Backends** are interchangeable behind two methods
  (`log_prob_of_continuation`, `generate_alternatives`); add a new model by
  writing a third backend with the same two methods.
- The trickiest piece is `log_prob_of_continuation` — it turns a causal LM's
  next-token predictions into `P(continuation | context)`. The offset between
  "position i" and "token i+1" is commented in detail there.
- `narrative_twist()` returns `None` when a probability can't be computed
  (empty continuation / no usable alternative); the pipeline skips those rows.
- The Hebrew run is the slow part (~a few minutes per participant on the 7B).
  Scores are deterministic for a fixed `--seed`.
